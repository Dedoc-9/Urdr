# `cohort` shipped `B // max(k, 1)` and carried, for several rungs, a stated and UNRUN protocol:
# measure end-to-end verification cost against k on a real corpus; if cost is maximal at k = 1 rather
# than at k = 0, the peaked charge is correct. One commit ago it registered C1-C5 against that
# measurement, WITH the classifier, so the rule could not be chosen once the numbers arrived. This is
# the measurement.
#
#   THE HEADLINE IS NOT WHICH ARM HELD. IT IS THAT THE SHIPPED ONE-LINE FALSIFIER, TAKEN AT ITS WORD,
#   WOULD HAVE ADOPTED THE PEAKED CHARGE.
#
# The protocol component IS maximal at k = 1: 6 fetches against 5 everywhere else. Read that sentence
# with the numbers in hand and no registration to answer to, and the peak is adopted. It should not
# be, for two reasons a committed prediction makes it natural to state and a post-hoc reading makes it
# easy to skip: the component that peaks is NOT the one the schedule is a schedule for, and the k = 1
# reading is a FAILED verification exhausting the peer list rather than a dearer success. Restricted
# to the members whose outcome is the same, the protocol cost is FLAT -- 5, 5, 5.
#
# panel   -- both cost components over the declared corpus in ascending k, their three shape verdicts

# constant in k because the population's capture noise lies BELOW the gap. At k = 1 there is no

# 16 disagree, agreement never reaches the threshold and the loop exhausts the list to COHORT_FAILED.

# fixture being under-specified rather than over-tuned, which is not the direction that was feared.
