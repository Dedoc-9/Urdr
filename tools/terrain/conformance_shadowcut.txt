# THE MAX-FLOW COLUMN IS THE CROSS-SECTION AND NOTHING ELSE. It does not move when the wall gets
# thicker, because it is not measuring the wall: it counts how many INDEPENDENT TUNNELS could be
# driven through the cross-section at once, one per cell of a layer. `cohort` asks what ONE tunnel
# COSTS. Those are dual questions, and the duality is the whole problem.
#
# WHY THE SHAPE IS WRONG, AND `cohort` HAD ALREADY MEASURED THE REASON. The quantity `min_cut`
# computes is a minimum-weight PATH — the fewest wall cells lying on any face-to-face route, since
# deleting exactly those opens it, and any deletion that opens the wall contains some route's wall
# cells. Max-flow computes a minimum CUT. Turning a min-weight path into a min cut is planar duality,
# and `cohort.hex_duality_fails_in_3d` is an EXISTING LAW OF THE VERY MODULE the remedy was proposed
# for, measured on a 7-cube, stating that the two-dimensional Z2 duality does not lift to three. THE
# REMEDY REACHED FOR A DUALITY ITS OWN SUBJECT HAD ALREADY REFUTED, one law away in the same file.
#
# The refutation is UNPACKED rather than handed back: `hex_duality_fails_in_3d` returns a TRIPLE, and
# a non-empty tuple is truthy whatever it contains, so a law that returned it directly could never
# fail. The first draft of `the_duality_it_needed_was_already_refuted` did exactly that.
#
# THE ACTUAL FIX IS SMALLER THAN THE PROPOSED ONE. A minimum-weight path over node weights of ZERO
# for free and ONE for wall is decided by a 0-1 BFS in linear time with no cap at all.
#
# THE BOUND IS INACTIVE ON THE PINNED CORPUS AND ACTIVE IMMEDIATELY OUTSIDE IT. Across the five cases
# `cohort.gap_table` actually pins, every answer is decided and the two formulations agree — so the
# `None` branch is unreachable there and THE PINNED GAP FIGURES WERE NEVER ARTEFACTS OF THE SEARCH
# HORIZON, which is the reassurance the shadow was built to be able to withhold. One step outside, at
# a wall of thickness four, the enumeration returns `None` and the path oracle returns 4.
# `CUT_SEARCH_MAX` is not a dormant limit; it is one ordinary wall away.
#
# EVERY ANSWER IS WITNESSED BY THE SUBJECT'S OWN PRIMITIVE. The path oracle does not merely report a
# number: it returns the wall cells it would delete, and the law removes exactly that set and asks
# `cohort.free_reaches` — the production flood fill — whether the wall opened, then removes one cell
# fewer and requires that it did NOT. The oracle proposes and the SUBJECT adjudicates, so a defect in
# the oracle's own bookkeeping cannot certify itself.
#
