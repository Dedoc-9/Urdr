# URDRSES1 conformance — MEMBERSHIP IS A PROPERTY OF THE EVENT, NOT OF THE ROOM. The Stage 5 SESSION
# law `compose` declared as its successor, built on a peer set that CHANGES. Session IS
# worldpeer.WorldPeer with ONE precondition added; nothing below the interface line moved.
#
# THE QUESTION, AND IT HAS EXACTLY TWO ANSWERS. An event arrives from a peer who WAS a member when
# the event happened and is NOT one now. Either membership is evaluated at the EVENT's tick or at the
# RECEIVER's head. Both are implementable and both are defensible in prose. They are not two
# policies: evaluated at the head, admission depends on WHEN THE ENVELOPE HAPPENED TO ARRIVE, so two
# conforming peers holding the identical event set land on different worlds.
#
#     membership at the EVENT tick     1 distinct chain   == the batch oracle
#     membership at the HEAD           3 distinct chains  != the batch oracle
#
#     Four delivery schedules, eleven identical envelopes, 22 rollbacks, 0 refusals on the law arm.
#     The oracle is INDEPENDENT: worldstep.simulate in batch on the calendar-filtered log, which
#     knows nothing about sessions, rollback or delivery order.
#
# THE SECOND WRONG DESIGN LANDS ON THE FIRST WRONG WORLD. Departure implemented by striking the peer
# from the ROSTER produces the SAME three chains as the head-time defect, digest for digest, on the
# same schedules. The only thing separating them is the typed refusal -- AUTH-REFUSE from the
# eviction, SESSION-REFUSE from the head-time test, same events, same world. The codes carry the
# information the state does not. THE ROSTER AND THE CALENDAR ANSWER DIFFERENT QUESTIONS AND CANNOT
# BE MERGED: a departed peer's signature must still verify, or the session's own history stops being
# checkable.
#
# THE ADMITTED SET IS LOAD-BEARING IN BOTH DIRECTIONS IN TIME, and only one direction is easy to see:
#
#     cuts where an admitted event is still QUEUED (tick >= head)   10 of 10 diverge
#     cuts where every admitted event has already been APPLIED       9 of 43 diverge
#
#     Forward it is certain; backward it is contingent on a later rollback reaching past the cut. A
#     suite built on late deliveries alone -- the schedule that LOOKS like the interesting one --
#     would meet the defect at roughly one cut in five. Priced, not asserted.
#
# SEGMENTATION UNDER A CHANGING PEER SET: 0 divergences over every cut of every in-horizon schedule
# (53 cuts). `compose` proved this over a fixed log; here the log arrives out of order, through
# rollbacks, while the peer set changes.
#

#
#     drop_known     the admitted set dropped from the snapshot     19 of 53
#     perturb_live   one word moved in the LIVE state only          27 of 53
#     perturb_all    the same word moved in the retained snapshots  53 of 53
#
#     perturb_live is ERASED wherever a later rollback restores from a retained snapshot, so its
